Safety & Moderation

Last updated: August 2026 · Support: zain.tariq@mail.com · Child safety: saudbilal1999@gmail.com

This document explains exactly how Huzz tries to prevent sexual harassment, sexting, scams, and abuse. It describes the real systems in our app today, not marketing language.

18+ only. Huzz is not for minors. Age verification, reporting, blocking, and moderation exist to keep adults safe on the platform.

1. Age verification (ZoiVera)

Before a user can like profiles, match, send messages, join clubs, or use Live Random, they must pass an 18+ age check.

Provider

We use ZoiVera for facial age estimation.

How it works

  1. The scan runs on the user's device (camera access required for the check).
  2. ZoiVera returns a signed attestation token (JWT) if the estimated age meets our 18+ threshold.
  3. Our Firebase Cloud Function finalizeZoiVeraAgeCheck verifies that token against ZoiVera's public keys (JWKS). We confirm the token belongs to the signed-in user and that verification passed.
  4. We store only a pass/fail result on the user profile (ageChecked18Plus, provider, method, timestamp). We do not store a gallery of face photos for dating features.

If verification fails or the user is under 18, core features stay locked.

2. Protecting against sexting & sexual messages

Huzz uses multiple layers. No system is perfect, but we combine automatic blocking, keyword detection, admin review, and user reports.

Layer A: Block before send (profanity filter)

  • When a user tries to send a chat message, the app calls our Cloud Function checkMessageToxicity.
  • This uses the bad-words profanity library to detect vulgar or offensive text.
  • If blocked, the message is not sent.
  • The attempt is logged in Firestore collection vulgarAttempts with the user ID, match ID, and timestamp.
  • A safetyEvents record is created and the user's userSafetyProfiles risk score is updated.

Layer B: Sexual & harassment keyword scan (on send)

  • Messages that pass the profanity gate are also scanned client-side by scanMessageText.
  • We maintain keyword lists for categories including sexual (e.g. explicit sexual terms, requests for nudes) and harassment (e.g. slurs and abusive language).
  • Flagged messages may still be stored but are marked in message metadata (moderation.flagged, categories, matched terms).
  • An automatic report is created in the admin reports queue for staff review.
  • Additional safetyEvents are recorded for the sender's safety profile.

Layer C: Profile photo moderation (NSFWJS)

  • When a profile photo is uploaded to Firebase Storage under images/{userId}/, a Cloud Function runs NSFWJS (TensorFlow image classifier).
  • Images scored as Porn, Hentai, or Sexy above our threshold are deleted from storage and removed from the user's profile.

Layer D: User safety profiles & risk scoring

Our backend builds a rolling safety profile per user from events in the last 7 and 30 days, including:

  • Sexual language flags
  • Harassment / profanity blocks
  • Manual reports from other users
  • Spam and copy-paste opener signals
  • Scam-risk patterns

Users crossing thresholds (for example repeated sexual language or multiple unique reporters) are marked for watch, review, or restricted status. Admins see recommended actions in the staff dashboard.

Layer E: Human moderation

  • Authorized Huzz staff use an Admin dashboard to review open reports, safety profiles, and blocked profanity attempts.
  • Staff can send formal moderation notices, restrict accounts, disable users, and ban devices (see below).
  • Moderation evidence can be exported for investigation.

3. Block feature

Any user can block another user from their profile or chat.

  • Block is stored at users/{yourUid}/blocks/{blockedUid}.
  • The match conversation is marked blocked so messaging stops immediately.
  • Blocked users can be viewed and unblocked in Settings → Blocked users.
  • Blocked users should not appear in discovery for the blocker (filtering depends on active session data).

4. Report feature

Users can report profiles, messages, or behavior from inside the app.

  • Reports are stored in Firestore collection reports with reporter, target, reason, categories, match ID, and status (open by default).
  • Manual reports from users create a safetyEvents entry for the reported user.
  • Automatic reports are created when keyword moderation flags a message.
  • Mehram supervisors can also report a user on behalf of the sister they supervise (see Mehram section).
  • Child safety reports are prioritized. Email saudbilal1999@gmail.com for urgent CSAE concerns.

5. Device ban

For serious or repeat violations, admins can ban a physical device, not just an account.

  • On login and app open, Huzz collects a device hash (derived device fingerprint) and checks bannedDevices/{deviceHash} in Firestore.
  • If the device is banned, the user is signed out automatically and cannot use the app on that device until the ban is removed by staff.
  • Device bans are used for repeat offenders who create new accounts after a profile ban.

6. Mehram supervision (accountability)

Mehram is an optional feature for female participants in a private chat who want a trusted supervisor (brother, father, friend) to watch the conversation.

How invite works

  • Only the female participant can create a Mehram invite, and only after the chat meets a minimum activity gate (about 10 minutes or 2+ messages).
  • She chooses view only or view + reply.
  • A secure link is generated (huzz://mehram?t=...). The token is hashed on our servers; the raw secret is never stored in plain text.
  • Links expire after 7 days. The girl can revoke access or regenerate the link at any time.

What the Mehram sees

  • The Mehram opens the link in the Huzz app. They do not create a dating profile.
  • They receive a temporary Firebase login limited to that one chat.
  • They see live messages. Mehram replies are labeled clearly so both chat participants know it is the supervisor speaking, not the sister.

Mehram safety actions

  • Report: sends a report to moderators; supervision can stay active.
  • Block: blocks the guy on the sister's account and ends Mehram access.
  • Leave: ends the Mehram session; the link may work again if access is still active.

Both the guy and the girl see a Mehram banner in chat when supervision is active.

7. Other safety features

  • 18+ gate on features: likes, matches, chat, clubs, and live require verified age.
  • Location: approximate city/country for matching; users control device location permission.
  • Contacts access: optional safety-related feature as described in-app and in our Privacy Policy.
  • Live Random: only verified users; either party can leave a session; session messages can be reported.
  • Clubs: group rules apply; reports and blocks work the same as elsewhere.
  • Account disable: admins can disable accounts that violate policy.
  • Force update alerts: admins can require a minimum app version for security fixes.

8. What we do not do

  • We do not read every message with human eyes in real time.
  • We do not guarantee that all inappropriate content will be caught before it is seen.
  • We do not run criminal background checks on users unless we explicitly state otherwise in the future.
  • Keyword lists and NSFW classifiers can have false positives and false negatives.
