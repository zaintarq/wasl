# Wasl features — 27 August 2026

A plain-language record of what we built and shipped today. Remote tip: `fde9a7e` on `master`.

---

## Live Vision safety checks

During a random Live video call, the app quietly takes a still frame from your own camera preview every few seconds and sends it to Google Cloud Vision Safe Search. If the frame looks adult or racy (same standard we use for photo uploads), the Live session is ended, a safety event is logged, and you are sent back to idle without an automatic rematch. If Vision or the network fails, the call is allowed to continue so a outage does not kill Live for everyone.

---

## Shadowban and account appeals

Admins can shadowban a user so they still log in, but they no longer appear in discovery for other people. The shadowbanned person is not notified. Separately, when an account is disabled, the user can submit an appeal from inside the app. Admins review those appeals in an Appeals tab and can approve, reject, or convert the case to a shadowban instead of a hard disable.

---

## Delete your account immediately (with password)

In Settings, **Delete account now** permanently removes the user’s login and personal data after they re-enter their password and type DELETE to confirm. The server only accepts this if they recently proved their identity. The wipe covers profile data, related storage files, Mehram records tied to them, and Firebase Auth, and then sends a confirmation email. This is the Play-friendly “in-app delete that actually deletes” path, not just a ticket for later.

---

## Ask admins to delete (queue) and auto-acknowledgement

Users can still file a deletion or partial data-deletion request that goes into an admin queue. As soon as they submit, they get an acknowledgement email saying we received the request and aim to process it within 30 days. When an admin finishes the wipe, a second email confirms completion. Partial deletion clears profile media and storage while keeping the account; full account deletion removes the account.

---

## Wipe preview for admins

Before an admin taps **Delete data + email**, the app shows a clear checklist of what will be removed for that request type (full account versus partial data). They confirm again, then the wipe and confirmation email run. That reduces accidental wipes and makes the process auditable.

---

## Download my data (DSAR export)

From Settings, a user can request a packet of their data. Admins can also export a packet for any user from the deletions desk or the user directory. The server builds a JSON file and a ZIP, stores them privately, and returns time-limited download links (about seven days). The packet includes profile fields, stories, reports, deletion history, and messages they authored in matches, with sensitive tokens scrubbed.

---

## Crash log grouping

When the app reports a crash, the backend fingerprints the stack and message so the same bug is rolled into one group instead of flooding the admin list with duplicates. Admins see one card per issue with a count (for example ×50), plus the latest sample stack. Older logs that were recorded before grouping still get grouped on the device from the recent feed when needed.

---

## Mehram invite clarity

Adding a Mehram now walks through clear steps: choose view-only or reply, generate a private link, then copy or share it with a short checklist (install the app, trust the person, do not post the link publicly). Share text explains that the link only works inside Wasl/Huzz. Regenerating a link warns that the old link stops working. The manage screen shows whether the invite is waiting to be opened or the Mehram is viewing right now.

---

## Mehram session history

Every time a guardian opens or leaves a Mehram invite (or access is revoked or ended by a block), the visit is recorded. The girl who invited them can see those visits in the Mehram manage panel for that chat. The guardian can open **Session history** on the supervision screen to see visits on the current invite and a short local list of past opens on that device.

## What still needs a new app build

Cloud Functions, Firestore rules, and indexes for these features are already live on Firebase project `huzz-10264`. Anything that lives in the mobile UI (Live frame capture, delete-account modal, Mehram screens, DSAR buttons, crash grouping UI) needs a new Android AAB with a versionCode higher than 9 before testers on Play see it.
