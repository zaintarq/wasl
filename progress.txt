WHAT THE APP IS

React Native social connection app. Firebase Auth, Firestore, Storage, Cloud Functions client. Primary flows: sign up or log in, complete profile, swipe or like people, match requests that the other person approves, chat with read receipts and typing, unmatch from the matches list. Extra screens: date planning, verification, admin, staff, contacts block list, settings, profile, live random.


NAVIGATION (RootNavigator.native.js)

Stack navigator. No React Navigation bottom tabs component. The home screen draws its own nav buttons and calls onNavigate.

Registered screens and components:
  Welcome          WelcomeScreen.native.js
  Onboarding       OnboardingFlow.native.js (mode signup or login)
  TabHome          HomeScreen.native.js
  TabMatches       MatchListScreen.native.js
  ChatThread       ChatScreen.native.js (matchId in route params)
  DatePlanning     DatePlanningScreen.native.js (matchId)
  TabProfile       MyProfileScreen.native.js
  TabSettings      SettingsScreen.native.js
  TabLive          LiveRandomScreen.native.js
  Admin            AdminScreen.native.js
  Contacts         ContactsBlockScreen.native.js
  BlockedUsers     BlockedUsersScreen.native.js
  Verification     VerificationScreen.native.js
  Staff            StaffScreen.native.js
  Filters          FiltersScreen.native.js (country filter)

Route name constants live in src/app/navigation/routes.js.


STARTUP ROUTING (same file)

If Firebase has no user: initial route Welcome.

If user exists:
  checkUserRoleFromAdminCollection(uid)
    isAdmin   → initial route Admin
    isStaff   → initial route Staff
  else userService.getUserById(uid)
    profileComplete true      → initial route TabHome
    else                      → initial route Onboarding


GLOBAL GATES (RootNavigator, run after login)

LocationSyncGate, PushTokenGate, DeviceBanGate, PermissionsRequiredGate, LocationRequiredGate, NotificationListener.


HOME SCREEN (HomeScreen.native.js)

USE_MOCK_DATA is false in source. Discovery uses real Firestore data when connected.

Contains SwipeDeck, country filter, pending match request handling, location via expo-location, like and pass actions that create or update matches through firebaseService.


DATA LAYER (firebaseService.js COL object)

Collections referenced in code include: users, matches, reports, bannedDevices, liveRandomPool, liveRandomSessions, verifications, admin, vulgarAttempts, datePlans. Subcollection users/{uid}/notifications for in app notifications.


AUTH (firebaseService authService)

Email password sign up and sign in, Google and Apple providers present in imports, password reset, email verification send on sign up, profile updates. User document writes include country, matchCountry, images, bio, and related profile fields.
